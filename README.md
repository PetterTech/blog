# PetterTech · Ye Olde Blogge

Archive of the old cloud.kemta.net WordPress blog – 76 posts from 2011–2019 plus the About page – served at
[pettertech.com/blog](https://pettertech.com/blog/) as the GitHub Pages **project site** of `PetterTech/blog`.
It is a frozen archive. Hugo, no theme, no build dependencies besides Hugo itself; no cookies, no tracking.

- Look and feel follow the pettertech.com splash page (`PetterTech/PetterTech.github.io`): dark grey with a faint
  dot pattern, Montserrat + DejaVu Sans Mono, yellow accent, light mode with logo swap and yellow highlighter.
- Dark/light theme follows the OS by default. The toggle remembers the choice in localStorage under the **same key
  (`theme`) as the splash page**, so it carries over between pettertech.com and /blog/ (same origin). Picking the
  same as the OS goes back to "follow the OS".
- Every page shows an archive notice (text in `hugo.toml` → `params.notice`).
- Old URLs are kept: each post has `url: /index.php/YYYY/MM/DD/slug/` in its front matter
  (→ `https://pettertech.com/blog/index.php/…`), the About page is `/blog/about-2/`, RSS is `/blog/index.xml`.
- Everything is self-hosted (fonts, logos, favicon, images, downloads in `static/`) – nothing is loaded from the
  splash site or any third party.

## Layout

```
hugo.toml                       site config (baseURL, archive notice, Markdown, highlighting, minify)
content/posts/                  the posts (plain Markdown, no raw HTML), content/about-2/ the About page
archetypes/default.md           front matter for `hugo new content posts/YYYY-MM-DD-slug.md`
layouts/                        templates, no theme:
  baseof.html                   page shell; home.html (posts by year), page.html (post/About), section.html,
  taxonomy.html, term.html      categories/tags, 404.html, home.rss.xml (/blog/index.xml)
  _partials/                    csp.html (CSP + inline theme script), header, notice, footer, post-list,
                                content.html (prefixes /wp-content/… and /index.php/… links with /blog/)
  _shortcodes/unavailable.html  {{< unavailable "Image no longer available" >}} – note for a lost image/download
assets/css/site.css             layout + theme tokens
assets/css/chroma.css           code colours, generated by tools/gen-chroma.sh (do not edit by hand)
assets/js/site.js               theme toggle
static/                         fonts (+ licences), img/ (logos), favicon, wp-content/uploads/ (WordPress media)
tools/gen-chroma.sh             regenerates assets/css/chroma.css
tools/test/                     check_site.py (links, assets, CSP, URL parity), browser test (theme, CSP, images)
.github/workflows/hugo.yml      build + check + deploy on push to main (and manually)
```

CSS and JS are minified/fingerprinted by Hugo (`/blog/css/site.min.<hash>.css`); fonts and images are served as-is.

## Local development

Use the Hugo **extended** version from `HUGO_VERSION` in `.github/workflows/hugo.yml` (currently 0.169.0) –
download `hugo_extended_<version>_<os>-<arch>` from <https://github.com/gohugoio/hugo/releases>.

```pwsh
hugo server                                   # http://localhost:1313/blog/
hugo --minify --panicOnWarning                # production build into public/ (baseURL from hugo.toml)
python3 tools/test/check_site.py public       # links, images, fonts, CSP hashes, no third-party resources
bash tools/test/run-browser-tests.sh          # headless Chrome: theme toggle, CSP, images, fonts
```

`check_site.py public --old <old public/>` also compares the post/About URLs with an older build.

## Content-Security-Policy

Every page has a CSP meta tag (`layouts/_partials/csp.html`): `default-src 'none'`, and scripts, styles, images and
fonts only from this site. Consequences:

- **No raw HTML or inline styles in posts.** Posts are plain Markdown and raw HTML is switched off
  (`[markup.goldmark.renderer] unsafe = false`): Hugo drops a stray `<img>`/`<a>`/`style="…"` and warns, and the
  `--panicOnWarning` build fails. Images in posts are centred by `site.css`. `check_site.py` also fails on any
  `style` attribute or `<style>` element in the output.
- **No external images or embeds.** Copy files into `static/wp-content/uploads/…` and link them as
  `/wp-content/uploads/…`.
- **The inline theme script** (sets `data-theme` before the first paint, so there is no flash) is allowed by its
  SHA-256 hash. The hash is **computed at build time** from the script string in `csp.html`, so editing the script
  needs no manual hash update. It is byte-identical to the splash page's script, so the hash is the same as in the
  splash CSP (`sha256-YEEdA3otuHd8jL8QP8LsG67C6rzv7nxnKlAA7Hi9m+s=`). To check by hand:
  `printf '%s' '<script body>' | openssl dgst -sha256 -binary | base64`.
  JS minification is off in `hugo.toml` (`[minify] disableJS`) because the minifier would rewrite the inline script
  after the hash was computed; `check_site.py` verifies every inline script against the CSP.

## Maintenance notes

- **Hugo is bumped by hand** (Dependabot does not track it): change `HUGO_VERSION` in the workflow – one line –
  build locally with the same version and run the checks. The workflow installs the official release tarball,
  verified against `hugo_<version>_checksums.txt`, and builds with `--panicOnWarning`, so deprecations fail the
  build instead of piling up.
- **Actions** are pinned to commit SHAs with the tag in a comment (checkout v7.0.1, upload-pages-artifact v5.0.0,
  deploy-pages v5.0.1). Dependabot (monthly) bumps SHA + comment together. Least-privilege jobs: build gets
  `contents: read` only, deploy gets `pages: write` + `id-token: write`. `configure-pages` is not used: the
  baseURL is fixed in `hugo.toml`.
- **Posts** have only `title`, `date`, `url` (the old WordPress path, kept so links keep working), `categories` and
  `tags` in the front matter (`draft: true` while writing). Images: `![alt](/wp-content/uploads/…)`, optionally
  wrapped in a link to the full-size file. A file that is gone for good: `{{< unavailable "File no longer available" >}}`.
- **Links inside posts** use site-root paths (`/wp-content/uploads/…`, `/index.php/…`); `_partials/content.html`
  prefixes them with the base path (`/blog/`) at render time. This replaces Hugo's legacy `canonifyURLs` setting.
- **Code highlighting**: Chroma with CSS classes. A fence needs a language (```` ```powershell ````) to be
  highlighted. Colours: `bash tools/gen-chroma.sh [dark-style] [light-style]` (defaults `github-dark` and `github`).
- **Fonts**: the splash page's files (Montserrat SemiBold/ExtraBold, DejaVu Sans Mono) plus Montserrat Regular
  for post text, all subset to Latin with `pyftsubset` (same unicode ranges as the splash). Licences in
  `static/fonts/`.
- **Content changes made during the move off cloud.kemta.net** (for reference): images and attachment links that
  pointed at cloud.kemta.net now use the copies in `static/wp-content/uploads/`; links between posts point to the
  new URLs; `.LINK` lines in the PowerShell help blocks point to https://pettertech.com/blog/; the Xerox ZenPack
  1.0 `.egg` is rehosted in `static/wp-content/uploads/2011/05/`; the SmtpDiag link goes to the archived Microsoft
  download page (Wayback Machine). Images and downloads that were hosted on Dropbox (public links dead since 2017,
  not in the Wayback Machine) were replaced by the local copy where one existed, otherwise by an "Image/File no
  longer available" note. Code fences got a language, and a few `<placeholder>` texts that the browser swallowed
  as HTML tags are escaped. All WordPress leftovers are gone: export-only front matter (`author`, `type`, the
  `wp-syntax-cache-content` plugin cache), WordPress image/link markup (`wp-image-*`/`align*` classes, attachment
  links, `srcset` thumbnails, `target="_blank"`), `<br />`/`<p>` wrappers and `&nbsp;` spacer lines – all now
  plain Markdown. WordPress's resized `-WxH` copies (and a few other files) in `static/wp-content/uploads/` are
  not used by any post any more but stay in place, so old URLs keep working.
